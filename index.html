Go

Distributed Job Queue

Kill a worker mid-job. Nothing is lost.

Go · PostgreSQL · Docker

A background job system with an HTTP API and independently deployed Go workers. Workers claim jobs from PostgreSQL with FOR UPDATE SKIP LOCKED and hold a time-limited lease. If a worker is kill -9’d, another worker reclaims the job and finishes it, and a fencing token makes sure the stale worker can never overwrite the newer result.

0duplicate claims200 jobs × 12 concurrent claimers, integration test
kill -9safecrashed worker’s job reclaimed and finished by another
1coordination pointPostgreSQL only: no Redis, no broker

Leases

Each claim is one atomic SQL statement and comes with a time-bound lease. All lease math uses database time, never worker clocks.

Fencing tokens

Every claim mints a new token. A late acknowledgement from a frozen worker is rejected.

Retries + dead letters

Exponential backoff with jitter (2s, 4s, 8s…). Jobs that run out of attempts go to a dead-letter state with full history.

Live dashboard

Queue depth, throughput, worker heartbeats and a per-job event timeline, served by the API.

Java

DAG Orchestrator

Run every step that can run. Wait for the rest.

Java 21 · Spring Boot 3.3 · PostgreSQL · React Flow

A workflow engine that takes a declarative graph of tasks, checks it for cycles and missing dependencies, then runs independent steps in parallel while respecting prerequisites. Failed tasks retry with backoff, a terminal failure skips everything downstream, and the UI shows each node’s status live as the run executes.

Graph validation

Kahn’s topological sort catches cycles, self and unknown dependencies before anything runs.

Versioned definitions

Saving a workflow again creates v2, v3…; old versions are immutable.

Fail-fast + cancel

A terminal failure fails the run and skips every task not yet started. Cancel wins any race.

Restart recovery

On boot, tasks left running by a dead process are retried, or failed if out of attempts.

Mini SQL Engine

A database, from the lexer up.

C++20 · CMake · Docker

An in-memory relational query engine written from scratch. It loads typed CSV tables, parses a documented SQL subset, builds an execution plan and runs it, using hash indexes for equality lookups. EXPLAIN shows which access path the planner chose. No SQLite or other database underneath.
